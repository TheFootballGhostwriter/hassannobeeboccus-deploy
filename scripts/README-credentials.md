# Credentials for `weekly-report.mjs`

Nothing here is needed by the site. These are read-only reporting credentials for a
script that never ships — `scripts/` is in `.vercelignore`, and `/scripts/*` 404s in
production.

Put them in `scripts/.env.report`, which is gitignored. Do **not** put them in
`.env.local`: that file is regenerated by `vercel env pull` and your edits would be lost.

```
GSC_SA_EMAIL=<service-account>@<project>.iam.gserviceaccount.com
GSC_SA_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
BING_API_KEY=<32 hex characters>
```

`GSC_SA_KEY` is the `private_key` field copied verbatim out of the downloaded JSON,
escaped newlines and all. The loader converts `\n` back to real newlines.

Vercel and MailerLite need no setup here. The Vercel token is read from the CLI's own
`auth.json` after `vercel login`, and `MAILERLITE_API_KEY` comes from
`vercel env pull .env.local --environment=production`.

## Google Search Console

A service account is used rather than OAuth, so there is no refresh token to expire.

1. console.cloud.google.com → create a project.
2. APIs & Services → Library → enable **Google Search Console API**.
3. IAM & Admin → Service Accounts → create one. It needs **no IAM roles** — Search
   Console permissions are granted separately in step 5.
4. Open it → Keys → Add key → Create new key → JSON. It downloads once and cannot be
   re-downloaded; copy `client_email` and `private_key` out of it.
5. Search Console → the `https://hassannobeeboccus.com` property → Settings → Users and
   permissions → Add user → paste the `client_email` → permission **Full**.

Step 5 is the one that is easy to forget. Without it every call returns 403 even though
the credentials are valid.

The report reads Search Analytics (clicks, impressions, queries, pages) and inspects the
coverage state of every sitemap URL. Quotas are 1200 queries/min and 2000 inspections/day,
far above what a weekly run uses.

There is **no API for "Request indexing"** — the Indexing API is restricted to job posting
and broadcast event pages. Requesting indexing stays a manual job in the Search Console UI,
capped at roughly 10 URLs/day.

## Bing Webmaster Tools

Sign in → gear icon, top right → Settings → **API Access** → API Key → accept the terms →
Generate. One key covers every site that account has verified. Signing in with Google SSO
is fine; the key is issued per user regardless of how you authenticate.

Bing's endpoints take no date range. They return a trailing window and encode dates as
MS-Ajax strings, so the report cuts the window client-side.
